## Ordre d'instruction pour éviter les collisions
1. FIGER L'OBSERVATION : identifiants natifs, UTC, SHA, statut, domaine, preuve et objectif propriétaire sans mutation de source.
2. RECONSTRUIRE : graphe personne → agent logique → session(s) → contexte(s) fournisseur → continuité(s) → scopes → tâches/claims → PR/CI.
3. QUALIFIER : source de vérité, projection, intention, expérimentation, superseded, conflit, incomplétude, impossibilité d'accès.
4. REJOUER NON DESTRUCTIVEMENT : tests séparés en fixtures et sur branche de PR uniquement ; ne jamais réexécuter F1/correction de lease réelle depuis l'audit.
5. PROPOSER : changements minimaux, preuves attendues, risques de régression, rollback et GO/NO-GO par le propriétaire.
6. APPLIQUER UNIQUEMENT APRÈS MANDAT : dans cette PR unique si cela ne perturbe pas une autre mission ; aucun changement de main, aucun auto-merge.

## Limites de cette matrice

Elle vérifie la **structure et les points d'entrée des principaux modules**, mais **pas chaque ligne de tous les 445 fichiers**. Les registres géants `gacr-sessions` et `gacr-beacons`, les revues détaillées des PR historiques, toutes les décisions implicites dans 1 413 commentaires et tous les événements de communication GACR exigent encore des preuves complémentaires. Aucune conclusion sur la cause racine du « petit problème » n'est possible sans rattacher l'incident à des traces précises.
